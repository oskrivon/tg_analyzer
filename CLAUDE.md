# Project: Telegram Channel Analyzer

Сбор и аналитика **публичных** Telegram-каналов и групп: метаданные + вовлечённость
постов → метрики, health-score 0–100, категория, опциональный LLM-анализ контента;
хранение в PostgreSQL, экспорт в CSV.

## Стек

- Python 3.11+
- Telethon (MTProto-клиент Telegram)
- SQLAlchemy 2.0 (async) + asyncpg + PostgreSQL
- aiohttp / httpx
- Anthropic Claude / OpenRouter (опциональный LLM-проход)
- tenacity (retry)

## Документация — маршрутизация

При работе с документами используй СТРОГО эти файлы:

| Что записать | Куда | Формат |
|---|---|---|
| Архитектура, модули, зависимости | `docs/ARCHITECTURE.md` | Обнови нужный раздел |
| Как запустить / задеплоить / починить | `docs/RUNBOOK.md` | Обнови нужный раздел |
| План рефакторинга | `docs/REFACTORING.md` | Новая запись в `## Активный` |
| Новая задача или фича | `docs/PLAN.md` | Добавь в `## TODO` |
| Идея на потом | `docs/PLAN.md` | Добавь в `## Backlog` |
| Новое исследование | `docs/[ТЕМА]_RESEARCH.md` | Создай файл + ссылка в `docs/RESEARCH.md` → Активные |
| Исследование завершено | `docs/archive/`, обнови `docs/RESEARCH.md` → Архив | Однострочный вывод |
| Результат / что сделано | `docs/PROGRESS.md` | Новая запись СВЕРХУ с датой |
| Бенчмарк / замер | `docs/PROGRESS.md` | В раздел `## Бенчмарки` |
| Принятое решение | `docs/RESEARCH.md` | В раздел `## Решения` |

## Быстрые команды

Когда я говорю:
- "запиши в план" → `docs/PLAN.md`, раздел TODO
- "в бэклог" → `docs/PLAN.md`, раздел Backlog
- "сохрани исследование" → `docs/RESEARCH.md` + отдельный файл если нужно
- "решение принято" → `docs/RESEARCH.md`, раздел Решения
- "готово" / "сделано" → `docs/PROGRESS.md`
- "замерь" / "бенчмарк" → `docs/PROGRESS.md`, раздел Бенчмарки
- "в архив" → перенеси в `docs/archive/`

## Правила записи

- Новые записи — СВЕРХУ (новое первым)
- Дата в формате YYYY-MM-DD
- НЕ удаляй существующие записи
- Если в PLAN.md больше 30 задач в Done — перенеси в `docs/archive/plan-YYYY-MM.md`
- Если не уверен куда записать — спроси

```

├── run_llm_analysis.py       # Фаза 2: LLM-анализ контента (один канал)
├── run_llm_batch.py          # Фаза 2: LLM-батч + CSV-экспорт + версии промптов
├── services/                 # analyzer, scorers, category detector, LLM-клиенты
├── utils/                    # метрики, извлечение ссылок/текста, промпты, прокси
├── database/                 # async SQLAlchemy-модели, соединение, retry
├── notebooks/                # разведочный анализ + генератор синтетической выборки
├── data/sample/              # синтетический пример вывода (CSV)
└── docs/                     # Документация (этот шаблон)
```

## Важные правила кода

- Только **публичные** каналы/группы; контент постов не хранится — лишь агрегаты.
- Секреты ТОЛЬКО через `.env` (`TELEGRAM_API_ID/HASH`, `DATABASE_URL`, LLM-ключи).
- async/await везде, где I/O; ретраи через `tenacity`.
- Дешёвый проход (без LLM) — для триажа; дорогой LLM — только по прошедшим.
